## 修复 macOS 重查更新误报「已是最新版本」的 bug
- 用户报告（macOS）：发现新版本 → 点「下载并更新」开始下载 → 关闭更新窗口 → 再点「检查更新」→ 提示「已是最新版本」。
- 根因：主进程 `app:check-updates` 只防了 `isChecking` 重入，但没记录「已知有更新」的生命周期状态。关闭窗口只是隐藏弹窗（下载在后台继续，主进程 `isDownloading=true`），再点检查又调了一次 `autoUpdater.checkForUpdates()`；在下载进行中重查，electron-updater 会误报 `update-not-available` → 前端显示「已是最新」。
- 修复（`electron-main.js`，仅主进程，前端无需改）：
  1. 新增模块级状态：`hasUpdate` / `isUpdateDownloaded` / `lastProgress` / `availableVersion` / `availableReleaseNotes`。
  2. 事件里维护：
     - `update-available`：hasUpdate=true、isUpdateDownloaded=false、记 version+releaseNotes。
     - `update-not-available`：**清掉**已知状态（确实没更新）。**注意 error 事件不清除**，避免下载失败后丢掉「有更新」记忆（用户可重试下载）。
     - `download-progress`：记 lastProgress。
     - `update-downloaded`：isUpdateDownloaded=true、hasUpdate=true、更新 version。
  3. `app:check-updates` handler 加短路分支（在 `isChecking` 判断之前）：
     - isUpdateDownloaded → 直接重发 `downloaded` 事件
     - isDownloading → 直接重发 `downloading` 事件（带 lastProgress）
     - hasUpdate → 直接重发 `available` 事件（带 version+releaseNotes）
     - 都不满足才真正调 `checkForUpdates()`（走原 20s 超时兜底逻辑）。
- 验证：`node --check electron-main.js` 通过（SYNTAX_OK）。dev 模式桩 handler 与「updater 不可用」桩 handler 不受影响（在早返回的 if 分支里，不触碰新状态）。
- 备注：前端 `handleCheckUpdates` 点开时仍会短暂闪 `checking`（因为 `updateState !== 'downloaded'` 时设 `checking`），但主进程立即重发 `downloading`/`available` 事件会马上纠正，行为正确、仅一瞬闪动，未改前端（避免过度改动）。

## 日志策略对标 EasyOps 核对
- 用户问「日志这块对标 easyops 了吗」。逐行对比 `EnvSwitch/electron-main.js` 与 `EasyOps/electron/main.js`。
- 已对齐（与 EasyOps 一致）：`log()` 双写模式 = `[Main] ${msg}` 打控制台（无时间戳）+ `[ISO时间戳] ${msg}` 写入 `userData/logs/main.log`；`function log()` 声明走 hoisting；`uncaughtException`/`unhandledRejection` 处理器；日志路径 `logs/main.log`、时间戳格式。
- 合理差异化适配（非偏离）：
  1. `REAL_USER_DATA` 顶部先 `app.getPath('userData')` 捕获——dev 模式会把 userData 重定向到临时目录（治 Chromium 缓存写权限噪声），日志必须落真实 userData 下；EasyOps 不重定向故直接调 `app.getPath('userData')`。
  2. `fmtLog` 多参格式化（string/Error/object，循环引用降级 String），比 EasyOps 纯字符串 `log` 更强。
  3. `logErr(tag, ...args)` 带模块前缀（`[SERVER]`/`[WATCHER]`/`[UPDATE]` 等）。
- 冲突副作用：electron-main.js 日志从会话早期「重写 console.log/error/warn 自动落盘所有控制台输出」复杂版，回退成简洁 `log(message)` 版——反而和 EasyOps `log()` 更一致。当前文件**无散用 console.***（只有 log() 内部一处），全部走统一通道。
- ⚠️ 缺口（EasyOps 有、EnvSwitch 没有）：**缺 `showFatal` 崩溃弹窗**（`dialog.showErrorBox`，让用户看到崩溃原因而非静默闪退）+ `isUpdateRelatedError` 正则过滤（拦更新器专属 rejection 避免重复弹窗）。EnvSwitch 崩溃只写日志不弹窗。若要完全对齐需补这两项；用户尚未确认是否要加。

## 修复卡片「超高/样式错乱」真正根因：esbuild 压缩 flex 简写 bug（client/src/App.css .project-card）
